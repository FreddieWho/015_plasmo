# QA、可重复性与验收标准

## 1. 仓库与文件层

- 所有分析通过版本控制；
- 原始数据只读、派生数据可重建；
- 大文件使用 manifest/checksum，不在仓库重复存储；
- 每个分析目录有 README、配置、输入清单、输出表、QC、软件环境；
- 不允许只保存 notebook 的最终状态而无可从头运行的入口；
- 随机过程固定种子并记录。

## 2. M0 数据验收

- [ ] 每个物种标准学名、taxid、参考品系、assembly accession/version 已解析；
- [ ] NCBI 与 PlasmoDB 版本关系已记录；
- [ ] genome/GFF/CDS/protein ID 一致；
- [ ] assembly 质量和注释完整度可比较；
- [ ] 低质量或不完整物种已降级而非勉强纳入；
- [ ] 宿主/生态元数据有来源和置信等级；
- [ ] 所有必要数据公开、无需作者请求；
- [ ] 下载规模与存储预算明确。

## 3. WP1 验收

- [ ] 核/线粒体/顶质体分开；
- [ ] GC/AT 统计在 genome、CDS、非编码、GC1/2/3、四倍简并位点可复现；
- [ ] 结果在重复屏蔽、核心 orthogroup 和全注释集上比较；
- [ ] 物种树、分支支持和潜在长枝问题报告；
- [ ] 至少两个候选独立组成转换；
- [ ] 没有把组成直接写成突变率；
- [ ] Figure 1 的每个数据点可追溯到输入文件。

## 4. WP2 验收

- [ ] 同义密码子零模型保持氨基酸并记录其他约束；
- [ ] 氨基酸模型控制 orthology、同源位点、结构/功能与 LCR；
- [ ] 组成闭合效应被正确处理；
- [ ] 替代注释和代表转录本规则敏感性完成；
- [ ] leave-one-species/clade-out 完成；
- [ ] 显著性与效应量、置信区间、方向一致性同时报告；
- [ ] 残差表包含负结果和不稳定候选；
- [ ] Gate B 选择基于预设标准而非主观偏好。

## 5. WP3 验收

- [ ] 不同物种/平台在物种内标准化；
- [ ] stage metadata 与原文一致；
- [ ] transcript abundance 未被直接称为 translation rate；
- [ ] tRNA gene copy、abundance、charging、modification 分开；
- [ ] 至少两类独立功能证据；
- [ ] 候选不是由 P. falciparum 单一数据丰富度制造；
- [ ] 冲突证据被解释或标记 UNRESOLVED；
- [ ] 功能结果能更新一个明确 Claim。

## 6. WP4 验收

- [ ] 候选收缩为 1 个主机制、1–3 个节点；
- [ ] 机制路径与领域表型直接相连；
- [ ] 必需性、宿主选择性和逃逸评估彼此独立；
- [ ] 结构预测不被当作功能验证；
- [ ] 明确两个竞争机制；
- [ ] 新增实验若提出，能够区分竞争机制且成本最小；
- [ ] 目标期刊根据真实证据重新评估。

## 7. 图件验收

每张主图必须有：
- 一个句子级主张；
- 原始/派生数据表；
- 可复现生成脚本；
- 样本数与统计单位；
- 效应量/区间；
- 关键敏感性或对应 Extended Data；
- 不依赖颜色才能理解的标注；
- 物种名、基因 ID 和版本一致；
- 图题不超出证据级别。

## 8. 任务关闭标准

任务只有同时满足以下条件才可标记 DONE：
1. 交付物存在且路径固定；
2. 代码从清洁环境可运行或有明确容器/环境；
3. 输入/输出 checksum 完整；
4. QA checklist 通过；
5. evidence/claim/data registry 已更新；
6. 失败尝试和限制已记录；
7. 下一依赖任务不需要猜测上下文。

否则状态只能是 `PARTIAL`、`BLOCKED` 或 `FAILED_INFORMATIVE`。

## 9. 最终复现包

投稿前必须能在独立环境重建：
- 物种与数据 manifest；
- Figure 1–5 和 Extended Data；
- 主要统计表；
- Gate 决策和排除的候选；
- 环境锁文件/容器；
- 数据引用与许可；
- 一个从 raw/processed public data 到结果的顶层 workflow。
